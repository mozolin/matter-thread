# Espressif ESP-EMU

Официальный инструмент от Espressif — esp-emulator (или esp-emu) представляет собой современный легковесный эмулятор на базе Rust. Он разработан специально для симуляции чипов ESP32 на архитектурах RISC-V и Xtensa (включая ESP32-H2) и из коробки поддерживает периферию, Wi-Fi, BLE, а также **IEEE 802.15.4 (Thread/Matter)**.  
________________________________________  

## 1. Установка esp-emu под Ubuntu
Для работы вам понадобятся базовые зависимости и официальный бинарный инсталлятор.

### Шаг 1: Установка системных зависимостей
Обновите пакеты и установите утилиты, необходимые для сетевых интерфейсов (если планируется использование TAP) и сборки:
~~~
sudo apt update
sudo apt install -y curl bridge-utils tunctl iproute2
~~~

### Шаг 2: Автоматическая установка esp-emu
Espressif предоставляет готовые сборки для Linux x86_64 и ARM64. Выполните команду для загрузки и установки актуальной версии:
~~~
curl -fsSL https://raw.githubusercontent.com/espressif/esp-emulator/main/install.sh | sh
~~~
Скрипт скачает эмулятор в директорию ~/.local/bin/esp-emu.

### Шаг 3: Настройка переменных окружения
Добавьте путь к исполняемому файлу в ваш ~/.bashrc:
~~~
export PATH="$HOME/.local/bin:$PATH"
~~~
Перезапустите терминал или примените изменения: source *~/.bashrc*.  
Проверьте успешность установки:

## 2. Подготовка собственной прошивки для ESP32-H2
Эмулятор запускает объединенный бинарный образ (merged flash binary), скомпилированный в ESP-IDF.  
1. Настройте среду ESP-IDF (требуется версия с поддержкой ESP32-H2, рекомендуется v5.1 и новее).  
2. Выберите цель: idf.py set-target esp32h2  
3. Соберите ваш проект Matter/Thread (idf.py build).  
4. Объедините все части прошивки (Bootloader, Partition Table, App) в один файл merged_binary.bin с помощью встроенной утилиты:  
~~~
esptool.py --chip esp32h2 merge_bin -o merged_binary.bin @flash_args
~~~
(Файл flash_args генерируется автоматически в папке build после успешной сборки).  
5.	Также объединённый образ прошивки, содержащий загрузчик, таблицу разделов и приложение можно создать с помощью ESP-IDF:  
~~~
idf.py merge-bin
~~~

## 3. Настройка виртуальной Thread Mesh-сети через UDP
esp-emu имеет встроенный механизм перехвата 802.15.4 трафика (--elf флаг позволяет декодировать вызовы) и маршрутизации пакетов. Чтобы связать два или более экземпляров эмулятора для формирования Mesh-сети без физического железа, используется сетевой бэкенд.  
Для симуляции радиоэфира 802.15.4 в экосистеме Espressif применяется инкапсуляция кадров 802.15.4 в UDP-пакеты (аналогично тому, как это делает OpenThread Simulation / ot-simulation). Каждая нода отправляет свои широковещательные 802.15.4 кадры на определенный UDP-порт соседа или на общий мультикаст-адрес.  

### Вариант А: Использование встроенного UDP-туннелирования (рекомендуемый для тестов)
Запустите два разных терминала для имитации двух нод. Мы перенаправляем сетевой стек эмулируемых чипов.  
  
•	Экземпляр 1 (Нода Лидер/Маршрутизатор):  
~~~
esp-emu --chip esp32h2 --firmware ./merged_binary.bin --elf ./build/your_matter_app.elf --net user --thread-sim bind:9001,peer:127.0.0.1:9002
~~~
•	Экземпляр 2 (Нода Эндпоинт/Дочерняя):  
~~~
esp-emu --chip esp32h2 --firmware ./merged_binary.bin --elf ./build/your_matter_app.elf --net user --thread-sim bind:9002,peer:127.0.0.1:9001
~~~
  
### Вариант Б: Формирование полноценного Mesh через виртуальный коммутатор (TAP/Бридж)
Если стек Matter внутри вашей прошивки требует полноценного широковещательного обмена между нодами (например, обмен IPv6-пакетами через Thread), лучше всего связать их через Linux-бридж и TAP-интерфейсы. Кадры 802.15.4 обрабатываются внутри прошивки OpenThread, преобразуются в IPv6, а эмулятор через --net tap выводит их наружу.  
  
1.	Создайте сетевой мост и два TAP-интерфейса в Ubuntu:
~~~
sudo brctl addbr br0
sudo tunctl -t tap0
sudo tunctl -t tap1
sudo brctl addif br0 tap0
sudo brctl addif br0 tap1
sudo ip link set br0 up
sudo ip link set tap0 up
sudo ip link set tap1 up
~~~
2.	Запустите Экземпляр №1 на интерфейсе tap0:
~~~
sudo esp-emu --chip esp32h2 --firmware ./merged_binary.bin --net tap,ifname=tap0
~~~

3.	Запустите Экземпляр №2 на интерфейсе tap1:
~~~
sudo esp-emu --chip esp32h2 --firmware ./merged_binary.bin --net tap,ifname=tap1
~~~

### Как теперь сформировать Mesh-сеть?
У вас доступна интерактивная консоль прошивки (OpenThread/ESP CLI). Вы можете вводить команды прямо в терминал эмулятора.  
Запустите второй экземпляр в соседнем терминале (он у вас настроен на bind:9001,peer:127.0.0.1:9002) и выполните следующие действия:  
1.	Проверьте, видят ли ноды друг друга:  
В консоли первой ноды нажмите Enter (чтобы появилась строка ввода >) и введите команду для сканирования радиоэфира:  
~~~
matter esp ot_cli scan
~~~
Используйте код с осторожностью.
2.	Если прошивка поддерживает стандартный OpenThread CLI, настройте сеть вручную:
-	На первой ноде:
~~~
matter esp ot_cli dataset init new
matter esp ot_cli dataset commit active
matter esp ot_cli ifconfig up
matter esp ot_cli thread start
~~~
Используйте код с осторожностью.
Спустя 10-15 секунд проверьте статус:
~~~
matter esp ot_cli state
~~~
Она должна написать leader.
-	Получить активный dataset:
~~~
matter esp ot_cli dataset active -x
~~~
Будет [hex_строка] типа:  
>  
> 0e08000000000001000000030000144a0300001335060004001fffe00208b7b17ce751f8bc140708fdc5cc20292430190510a3adfdb9f4de26c327a2dc39d83c2103030f4f70656e5468726561642d623631380102b6180410367b6859fa8880cd506f3552bb4336550c0402a0f7f8  
>  
  
Или получить активный networkkey:
~~~
matter esp ot_cli networkkey
~~~
Будет что-то типа:  
>  
> a3adfdb9f4de26c327a2dc39d83c2103  
>  
  
-	На второй ноде:  
Чтобы дочерняя нода подключилась к первой, ей нужен тот же ключ сети. Получите данные датасета на первой ноде командой > dataset active raw (она выдаст длинную hex-строку), скопируйте её и введите на второй ноде:  
~~~
matter esp ot_cli dataset set active [вставьте_hex_строку]
~~~
или
~~~
matter esp ot_cli dataset networkkey a3adfdb9f4de26c327a2dc39d83c2103
~~~
и затем:
~~~
matter esp ot_cli dataset commit active
matter esp ot_cli ifconfig up
matter esp ot_cli thread start
~~~
Спустя 10-15 секунд проверьте статус:
~~~
matter esp ot_cli state
~~~
После этого вторая нода должна войти в сеть со статусом child или router.  
Проверьте список роутеров:  
~~~
matter esp ot_cli router table

На первой ноде:

## Интеграция в Home Assistant
Интеграция вашей виртуальной сети в Home Assistant — отличный способ полноценно отладить прошивку Matter.  
Поскольку Home Assistant общается с устройствами по протоколу IPv6, а эмуляторы сейчас изолированы внутри своего UDP-моста, нам необходимо связать виртуальный радиоэфир с сетевым стеком вашей Ubuntu. Для этого используется Thread Border Router (Граничный маршрутизатор).  
Ниже приведено пошаговое руководство, как пробросить вашу эмулируемую Mesh-сеть в реальную ОС и подключить её к Home Assistant.  
________________________________________  

### Шаг 1: Создание виртуального сетевого интерфейса (TAP) в Ubuntu
Чтобы выпустить Thread-трафик из эмулятора в ядро Linux, мы создадим виртуальный сетевой интерфейс tap0.  
Выполните в терминале Ubuntu:  
~~~
# Создаем TAP-интерфейс
sudo ip tuntap add dev tap0 mode tap
# Включаем IPv6-маршрутизацию на интерфейсе
sudo ip link set tap0 up
sudo sysctl -w net.ipv6.conf.tap0.forwarding=1
~~~
________________________________________  

### Шаг 2: Запуск третьей ноды — Thread Border Router (OTBR)
В экосистеме Espressif граничный маршрутизатор собирается из стандартного примера ESP-IDF examples/openthread/ot_br. Собранный образ OTBR запускается в третьем эмуляторе и выступает в роли «моста».  
Запустите третий терминал и перекрестите порты так, чтобы OTBR стал третьим участником вашего UDP-эфира.  
•	Концепция: Нода 1 (9001), Нода 2 (9002), OTBR (9003). Чтобы связать три ноды в один UDP-эфир, эмулятор использует встроенный сетевой бэкенд Linux. Но проще всего подключить OTBR к интерфейсу tap0:  
~~~
sudo esp-emu --chip esp32h2 --firmware path_to_ot_br/ot_br.bin --net tap,ifname=tap0 --thread-sim bind:9003,peer:127.0.0.1:9001
~~~
  
(После запуска на первой ноде выполните matter esp ot neighbor table, чтобы убедиться, что OTBR появился в списке соседей).  
В консоли OTBR привяжите Thread-интерфейс к созданному в Ubuntu интерфейсу tap0:  
~~~
otbr interface tap0
otbr start
~~~
________________________________________  

### Шаг 3: Синхронизация Thread Credentials с Home Assistant
Чтобы Home Assistant мог управлять устройствами, он должен находиться в той же Thread-сети, что и эмуляторы, либо знать её ключи шифрования.  
1.	Перейдите в веб-интерфейс Home Assistant: Настройки ➡️ Устройства и службы ➡️ Вкладка "Thread".  
2.	Если у вас используется официальный Home Assistant SkyConnect или настроен внутренний OTBR, вы увидите текущую Thread-сеть.  
3.	Нажмите «Изменить параметры» (или «Добавить сеть») и введите те самые сетевые данные (PAN ID, Extended PAN ID, Network Key), которые вы сгенерировали на первом шаге командой matter esp ot dataset active raw.  
4.	Теперь Home Assistant имеет общий виртуальный «радиоканал» с вашими эмуляторами через интерфейс tap0.  
________________________________________  

### Шаг 4: Добавление устройств в Home Assistant через Matter
Так как ваши эмулируемые чипы ESP32-H2 работают в режиме ожидания сопряжения (Server Listening...), они готовы к добавлению.  
1. В консоли первого эмулятора (mike_h2_multiclimate) введите команду для вывода кодов сопряжения:  
~~~
matter onboardingcodes ble
~~~
2. Скопируйте цифровой Manual Pairing Code (11-значное число).  
3. В приложении Home Assistant (лучше использовать мобильное приложение на смартфоне, так как оно использует Bluetooth телефона для первичного обнаружения эмулируемой ноды через сквозной интерфейс Ubuntu, либо выберите добавление «Без QR-кода» в веб-панели).  
4. Перейдите в Настройки ➡️ Устройства и службы ➡️ Добавить интеграцию ➡️ Добавить устройство Matter.  
5. Выберите «Ввести код вручную» и вставьте скопированный код.  
6. Home Assistant свяжется с эмулятором через tap0 и OTBR, выполнит процедуру CASE-сессии и добавит ваше виртуальное устройство mike_h2_multiclimate на панель управления. В этот момент в консоли эмулятора побегут логи вида CHIP[SVR]: Commissioning completed successfully.  


## Интеграция в существующую Thread-сеть 
Раз ваши 4 физических пограничных маршрутизатора (ESP OTBR) уже объединены в общую Thread-сеть и контролируются Home Assistant, вам вообще не нужно настраивать новые сети или мосты. Ваши виртуальные ноды в эмуляторе esp-emu могут просто «подсесть» в этот существующий живой радиоэфир.  
Чтобы виртуальные чипы ESP32-H2 из вашей Ubuntu увидели реальную сеть через физические платы, нужно решить две задачи: прокинуть радиокадры через UDP и синхронизировать параметры сети (Dataset).  
________________________________________  

### Шаг 1. Перенаправление радиокадров эмулятора на физический OTBR
Эмулятор esp-emu обменивается кадрами 802.15.4 через UDP-датаграммы. Чтобы ваши эмулируемые устройства оказались в одном «эфире» с физическими платами, перенаправьте их трафик на IP-адрес любого из ваших 4-х работающих ESP OTBR.  
1.Узнайте локальный IP-адрес одного из ваших физических ESP OTBR (например, 192.168.31.150).  
2. Установите socat в Ubuntu:  
~~~
sudo apt install socat
~~~
3. В Ubuntu запустите socat, чтобы связать локальные порты эмулятора с радиоинтерфейсом реальной платы:  
~~~
# Трафик первой виртуальной ноды пересылаем на физический OTBR
socat UDP4-LISTEN:9001,fork UDP4:192.168.31.150:9001 &
# Трафик второй виртуальной ноды пересылаем туда же
socat UDP4-LISTEN:9002,fork UDP4:192.168.31.150:9001 &
~~~
(Здесь обе ноды шлют пакеты на порт 9001 физического OTBR, так как для него это единая «воздушная» среда).  
________________________________________  

### Шаг 2. Извлечение параметров живой Thread-сети
Чтобы виртуальные ноды смогли авторизоваться в вашей существующей сети, им нужны точные сетевые ключи (Active Dataset). Извлечь их можно двумя путями:  
•	Путь А (Через Home Assistant): Перейдите в Настройки ➡️ Устройства и службы ➡️ Thread. Найдите вашу активную сеть, нажмите на иконку информации (i) и скопируйте Credentials / Сетевые данные (в формате Hex-строки).  
•	Путь Б (Через CLI любого OTBR): Если у вас есть доступ к консоли одной из плат, введите:  
~~~
matter esp ot_cli dataset active -x
~~~
Скопируйте полученную длинную шестнадцатеричную строку.  
________________________________________  

### Шаг 3. Подключение виртуальных нод к вашей сети
Теперь запустите оба эмулятора на Ubuntu с перекрестными портами для socat и введите ключи вашей реальной сети.  
1. Запуск и настройка первой виртуальной ноды:  
~~~
esp-emu --chip esp32h2 --firmware build/merged-binary.bin --elf build/mike_h2_multiclimate.elf --net user --thread-sim bind:9001,peer:127.0.0.1:9002
~~~
В консоли эмулятора скормите ему параметры вашей живой сети:
~~~
matter esp ot_cli dataset set active [ВСТАВЬТЕ_HEX_СТРОКУ_ВАШЕЙ_СЕТИ]
matter esp ot_cli ifconfig up
matter esp ot_cli thread start
~~~
  
2. Запуск и настройка второй виртуальной ноды:  
~~~
esp-emu --chip esp32h2 --firmware build/merged-binary.bin --elf build/mike_h2_multiclimate.elf --net user --thread-sim bind:9002,peer:127.0.0.1:9001
~~~
В консоли второго эмулятора повторите ввод:  
~~~
matter config discriminator 3841
~~~
(По умолчанию в прошивках Espressif discriminator равен 3840. Мы меняем его на 3841 для второй ноды).  
~~~
matter esp ot_cli dataset set active [ВСТАВЬТЕ_HEX_СТРОКУ_ВАШЕЙ_СЕТИ]
matter esp ot_cli ifconfig up
matter esp ot_cli thread start
~~~
  
Через 10-15 секунд проверьте статус на виртуальных нодах командой matter esp ot state. Они должны получить статус child или router. Это будет означать, что они успешно вошли в вашу существующую физическую сеть в качестве новых участников.  
________________________________________  

### Шаг 4. Добавление в Home Assistant
Так как ваши виртуальные ноды стали полноценной частью работающей Thread-сети, Home Assistant OS мгновенно увидит их IPv6-адреса через ваши физические ESP OTBR.  
1. В консоли первого эмулятора получите код сопряжения:  
~~~
matter onboardingcodes ble
~~~
2. В интерфейсе Home Assistant перейдите в Добавить устройство ➡️ Добавить устройство Matter ➡️ Ввести код вручную.  
3. Введите полученный 11-значный код.  
4. Повторите процедуру для второго эмулятора.  
Ваш виртуальный климатический контроллер mike_h2_multiclimate появится в Home Assistant рядом с вашими реальными физическими устройствами.  
  

## Как ещё проверить работу сети?
Анализ трафика: Вы можете запустить wireshark на интерфейсе br0 или tap0 в Ubuntu, выбрать протокол IEEE 802.15.4 или 6LoWPAN / Thread и в реальном времени смотреть, как виртуальные чипы ESP32-H2 обмениваются пакетами подтверждения, Matter-сообщениями и строят Mesh-топологию.
